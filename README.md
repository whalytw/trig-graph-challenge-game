# 三角函數・繪圖闖關 v1.4

三位學生同時在同一個觸控螢幕的左、中、右區各自闖關。純靜態網頁，沒有安裝程序，不依賴 CDN、登入或後端。

## 開始使用

1. 解壓縮 ZIP，保持 `index.html`、`style.css`、`engine.js`、`app.js` 放在同一個資料夾。
2. 直接用 Chrome／Edge 開啟 `index.html` 即可離線遊玩。
3. 點「教師設定」調整題目，儲存後點「全螢幕」。
4. 各區選填座號，按「開始挑戰」。完成後按「下一位學生」，其餘兩區持續遊玩。

## 上傳 GitHub Pages

將解壓縮後的檔案上傳至你要使用的 GitHub 儲存庫。網頁入口檔 `index.html` 需與其餘三個網頁檔案保持相同相對位置，請勿只上傳 ZIP。

若放在儲存庫根目錄，使用 Pages 的分支發布方式，選擇存放檔案的分支與根目錄。若與既有遊戲共用儲存庫，可整包放在 `trig-graph-game/` 子資料夾，網址在原本網站後加 `/trig-graph-game/`。

## 教師設定

每個星等可獨立設定倒數秒數，選項由 10～300 秒，每 10 秒一個選項。預設：

| 星等 | 1 星 | 2 星 | 3 星 | 4 星 | 5 星 | 6 星 |
|---|---|---|---|---|---|---|
| 題數 | 1 | 1 | 1 | 0 | 0 | 1 |
| 限時 | 40 秒 | 60 秒 | 80 秒 | 100 秒 | 100 秒 | 120 秒 |

三區各自倒數；時間到自動送出現有筆跡，空白作答得 0 分。教師修改秒數後，正在遊玩的學生沿用開始時的設定，下一位才套用新設定。

預設 1、2、3、6 星各 1 題，共 4 題；4、5 星預設略過。進度線每一段代表一題，依實際題數顯示，包含同星等的重複題目。沒有及格門檻，每題評分後 2 秒自動換題。每星等可設 0～20 題，0 題表示略過。6 星另外提供是否開啟的勾選項目。

| 星等 | 題目規則 |
|---|---|
| 1 星 | 原始 sin x、cos x、tan x；可複選出題類型 |
| 2 星 | 恰好 1 種圖形變化 |
| 3 星 | 恰好 2 種圖形變化 |
| 4 星 | 恰好 3 種圖形變化 |
| 5 星 | 恰好 4 種圖形變化 |
| 6 星 | a sin x + b cos x 的正餘弦疊合 |

2～5 星可各自勾選 sin／cos／tan，以及左右平移、左右伸縮、上下伸縮、上下平移。只從勾選的變化中取該星等需要的種類數。例如 2 sin(x − π/2) 恰有兩種變化，所以屬於 3 星。若勾選種類不足，系統會指出原因，不會將題目偷偷降級。

數字設定：

- 1～5 星使用 `a·f(b(x−h))+d`；振幅係數 a 為 1、2、3、4。
- 水平伸縮 b 為 1、2、1/2。水平平移 h 為 0、±π/2、±π，不使用 π/3 等位移。
- 上下平移 d 為 0、±1、±2；x 範圍固定為 [−2π,2π]，y 範圍依每題的振幅與上下平移自動調整，保留少量邊界及 x 軸。例如 sin x 使用 −1.5～1.5，振幅 4 的圖形使用約 −5～5；y 軸刻度採 0.5 或 1，畫面高度較小時會適度減少刻度標籤以避免重疊。tan 依倍率與中心位置設定可見範圍，畫面外部分不計分。
- 6 星係數的絕對值相同，採 1、√2、2、2√2；各項正負號隨機。疊合振幅為 √2、2、2√2、4，平移量為 π/4 的整數倍。避免需要計算反三角函數的係數組合。
- 全部六個星等的完整題庫共 916 種參數組合（可用題型依勾選與題數設定而定）。會盡量避開另外兩區的當前題目與自己最近的題目；當教師只開放極少題型時，題目可能重複，例如 1 星只勾選 sin x 時必然都是同一個基礎函數。

預設採深色主題，格線寬度 1.5 px。x 軸標籤顯示在真正 x 軸略下方，便於對照座標。π/2、3π/2 改用分子、水平分數線、分母的上下排版，負號置於分數左側。先畫標示，再畫學生筆跡與參考圖；筆跡會完整蓋過文字與底色，橡皮擦擦除後標示自然恢復。教師可設定「座標標示文字大小（px）」與「座標標示文字顏色」，同時套用到三區的 x、y 刻度及 x、y 軸名稱。預設大小 16 px，可設 10～28 px；窄視窗會適度縮小，避免刻度重疊。預設深色文字顏色為 #a8b9cf、淺色為 #65778c，自訂顏色會保留。主題、格線顏色與粗細套用到全畫面。座號預設 1～30，可調整至 1～99 內的範圍。設定只保存於目前裝置／瀏覽器，換電腦需重新設定。

修改題型、題數、限時、求救卡上限與座號後，正在遊玩的學生沿用開始時的設定；下一位學生使用新的設定，避免中途突然換規則。

## 每題求救卡

預設每題有 3 張求救卡，教師可在「每題求救卡」下拉選單設定 0～3 張；設為 0 時不顯示求救按鈕。三區分別記錄使用次數，每次換題重新配發。

- 將 −2π～2π 分成 8 個寬度為 π/2 的區間。每張卡隨機選取一個尚未揭示的區間，同一題不會重複。
- 清除該區間的學生筆跡，顯示正確函數圖，並以薄霧矩形標示鎖定區域。深色主題使用粉紅色解答線，淺色使用紫紅色，與三區的學生筆跡區分。
- 學生只能畫未鎖定的區間。筆畫跨過求救區間時會分開保留兩側，不會用直線穿過霧區。
- 橡皮擦與復原不能清除求救解答，也不會退回使用次數或恢復該區間的舊筆跡。求救解答不耗學生墨水，清除原筆跡後重新計算墨水用量。
- 求救區間在原始評分中視為正確作答，再依使用次數將整題分數乘上 `0.8^次數`，最後才四捨五入為整數，不逐次四捨五入。

| 使用張數 | 整題分數倍率 | 原始評分 100 分時的得分 |
|---|---|---|
| 0 | 1 | 100 分 |
| 1 | 0.8 | 80 分 |
| 2 | 0.64 | 64 分 |
| 3 | 0.512 | 51 分 |

尚未完成的其他區間仍會扣分；僅使用求救卡並不等於整張圖完成。時間到自動送出時，同樣計入求救區間與倍率。總分加總各題扣分並四捨五入後的得分。

## 手寫操作

- 細筆寬度為 2.2 CSS px，支援手指、觸控筆或滑鼠。
- 每區可獨立追蹤一個手指／筆，三區可同時操作，前提是瀏覽器實際收到各自的獨立接觸點。跨過區域邊框不會在鄰區留下筆跡；離開繪圖範圍後重新進入，也不會用直線連起中間空白。
- 工具與送出按鈕於接觸時立即觸發，接受非主要接觸點；快速點按、長按均不需等放開才生效。一次長按只操作一次，相容的後續 click 不會重複復原。切換工具或復原會先結束本區的現有筆畫，避免遺失放開事件後無法操作；其他區繼續繪圖。
- 筆跡按畫面更新批次處理；墨水判定增量更新新線段經過的 x 位置，減少三人繪圖時反覆掃描全部筆跡的計算。擦除、復原後重建墨水資料。
- 橡皮擦沿接觸路徑擦除部分筆跡；「復原」可復原最近 12 次操作。
- 使用隱藏墨水用量：以繪圖座標換算的軌跡長度計算，與螢幕解析度無關。用量依題目的可見曲線長度分配，避免高頻率或 tan 題目先天容易耗盡。
- 同一 x 位置若出現超過 6 個不同的 y 筆跡，也會立即停筆。判定採細密 x 掃描與小量容差，合併重複描繪及手寫抖動，不把筆寬誤算成多個值。
- 耗盡後橡皮擦仍可使用，擦除筆跡後會重新計算兩項限制。兩項限制均解除才恢復細筆。
- 網頁攔截長按右鍵選單、拖曳、文字選取與繪圖區的縮放／捲動手勢，避免誤觸干擾遊玩。

## 評分與過關

1. 將 −2π 到 2π 平均分成 40 段，在每段中點取一個固定 x 值。
2. 求救區間內的取樣點視為正確作答。其餘位置用學生線段與該 x 的交點插值求 y；沒有筆跡交點即該點得 0 分。
3. 在每點比較誤差 `|學生 y − 正確 y|`。0.12 單位內視為手寫容差，超出後線性扣分，誤差達 0.92 單位時該點得 0 分。
4. 同一取樣 x 有多個不同 y 時，先平均所有交點的準確度，再除以交點數的平方根；不能靠多畫幾條線取得更高分。
5. 將有效取樣點得分平均後乘以 100，再乘上 `0.8^求救卡使用張數`，最後四捨五入至整數。未畫到且未求救的有效點仍列入分母；沒有使用求救卡且只畫半張圖時最多約 50 分。
6. tan 的正確 y 超出當題顯示範圍或沒有定義時，該點不列入評分。結果會顯示比對的有效點數；各分支應分開畫，不必畫漸近線。

送出或時間到後顯示參考答案虛線、取樣點、完整度與得分；不論分數多少，2 秒後自動進入下一題。最後一題評分後也等待 2 秒，再顯示總分。總分為全部題目分數相加，每題滿分 100；預設 4 題滿分 400，另外顯示各星等加總與平均分數。

## 全螢幕版面

桌面版使用實際視窗高度配置三個區域，不再使用會強迫整頁捲動的固定最小高度。一般與短視窗都有相應的控制列高度，送出按鈕留在畫面內；繪圖區使用剩餘空間。老師的設定視窗可以內部捲動，不影響遊玩版面的高度。

## AirSync 與三人觸控排查

教師設定內可開啟 `touch-test.html` 診斷頁，也可直接開啟該檔。這個頁面獨立執行，不會送出或清除原遊戲成績。

1. 用目前的 AirSync 連線，三位學生各在一區同時按住並移動 3 秒。記下「最多同時」、輸入類型，以及各區接觸次數是否符合實際點按次數。
2. 用 HDMI 加上對應的 USB Touch 回傳線，改有線連接同一台筆電與 IFP，再執行相同測試。僅接 HDMI 不會回傳觸控；Touch 端口需與選用的影像輸入配對，請依機身標示／操作手冊接線。
3. 若 AirSync 下只收到 1 個 mouse，而有線能收到 3 個不同 touch ID，可把問題縮小到無線回傳路徑的輸入轉換／設定；網頁不能重建根本沒有傳到瀏覽器的接觸點。
4. 若兩者都能同時收到 3 點，但 AirSync 明顯延遲，較支持網路／投影／回傳流程造成延遲的可能。若有線也不正常，需再檢查驅動、接線、瀏覽器與裝置的觸控設定。

IFP8653 官方規格列出 Windows 40 點、Android 20 點觸控，這是硬體能力，不代表每種無線投影方式都提供相同的瀏覽器輸入。AirSync 官方說明支持 Touchback，並提醒其多來源投影分割畫面可能不準確，建議投影來源先全螢幕；此處指 AirSync 的投影分割模式，遊戲內的三個區域仍可照常使用。查閱的官方資料未明確保證 Windows Touchback 會向瀏覽器回傳三個獨立觸控 ID。

官方亦指出網路品質不佳會造成畫面延遲，建議 LAN 分享或讓 IFP 接網路線。這能支持把 AirSync 當作排查對象，不能直接證明目前教室的問題全由 AirSync 引起。請使用 AirSync Sender 程式，確認 Touchback 開啟；Web Sender 不提供觸控回傳。

## 升級設定

從 v1.2 起，首次讀取更早的舊版設定時，與舊預設相同的秒數、淺色主題、預設格線顏色與 1 px 格線寬度會更新成新預設；若六星題數全為 1，也會改成 1、1、1、0、0、1。不同於舊預設的自訂值保留。由於舊版沒有記錄某個預設值是否曾被手動選取，恰好與舊預設相同的值一樣會升級。此轉換只執行一次。v1.3 會在既有設定補入新的座標標示大小及顏色；v1.4 補入每題 3 張求救卡，其餘既有設定沿用。

需要完整新預設時，在教師設定按「恢復預設設定」，再按「儲存設定」。上傳新版時請同時更新 HTML、CSS 與兩支 JS，避免混用不同版本；已開啟舊頁面的瀏覽器請重新整理。

## 檔案內容與驗證

- `index.html`：遊戲入口。
- `style.css`：三區版面、淺色／深色主題。
- `engine.js`：題庫、取樣、評分及墨水計算。
- `app.js`：手寫操作、闖關與設定。
- `touch-test.html`：獨立三人觸控診斷。
- `tests/engine.test.cjs`：可用 Node.js 執行的數學與評分檢查。
- `tests/help.test.cjs`：求救區間、筆跡裁切、倍率與四捨五入檢查。
- `驗證紀錄.txt`：本版本驗證範圍。

重新整理會清除當前遊戲與成績，但保留教師設定。此版本沒有跨裝置成績保存功能。
